Summary

An Intelligence Manager is one person accountable for a company’s AI, from what it costs to what it returns. Most companies currently staff this work in pieces under several titles, often before recognizing that it needs a single owner. I perform the full role: I allocate each step of a workflow to a model, to conventional software or to a person; reduce the cost of each result; build and deploy the agents, with guardrails and human approval where the risk requires them; and report results in figures a finance team can audit. I have operated my businesses this way with full profit-and-loss responsibility, have held supervisor and trainer roles at several employers, and build the systems myself in Python and TypeScript.

Measured Results

  • Spend efficiency. Ran 164,039 model calls across 1,416 agent sessions in 58 days on one flat-rate plan that cost about $380 for the period. 96.5% of input tokens were served from the prompt cache. The same work would have been billed at about $17,000 at list API prices, or about $142,500 without the cache. Figures come from Claude Code’s own usage records.
  • Quality and routing. On a 71-question test of my live customer-service agent, cut wrong answers from 3 to 0. Of the 23 cases still handed to a person, 21 were policy the business had not yet decided, so I sent them to the owner as decisions to make.
  • Model cost. Moved a grading step from a premium model to a lower-cost one only after the cheaper model passed a calibration set in which about half the answers are built to fail.
  • Capacity governance. Cut parallel agents from 20 to 5 after a burst used a five-hour plan allowance in about 90 minutes, and set a per-agent GPU limit so several workloads share one machine without stopping each other.
  • Risk. Took my production agent offline when it answered questions the business had not decided, and turned it back on only after each new guard was proven by a test that fails without it.

Spend and efficiency

  • Implemented production cost governance: output-token and chat-history caps, an 8-step limit per run, per-visitor and daily call limits, and a manual shutoff.
  • Prioritized the lowest-cost path that passes evaluation: a flat-rate subscription before metered API calls, local open models before frontier models, and stored answers when retrieval confidence is high.
  • Built an agent run budget that prices each call before execution and stops the run at its cost or step ceiling, and an LLM gateway with cross-provider failover, circuit breakers, rate limits and an exact-match response cache.

Workflow design and human oversight

  • Mapped each workflow with the people who run it, and assigned each step to an agent, to conventional code or to a person for approval.
  • Designed reason-coded handoffs that pass the transcript to a person, scored in evaluation so a correct handoff counts as a pass and an unneeded one as a miss.
  • Separated “the answer was not found” from “the business has not decided this” in the agent’s retrieval, so policy gaps are escalated to the owner and never guessed.

Measurement and governance

  • Established a 103-scenario live evaluation with an answer-rate floor of 0.8 that is never lowered without a written reason, and a CI gate that fails the build on LLM or RAG regression and rejects an empty baseline.
  • Kept final decisions with a person in compliance tooling, where a model may add a reviewer note but cannot change a verdict.
  • Enforced model license terms by keeping outputs of a model whose license excludes the United States out of every published or client-facing work product.
  • Verified every public claim against the code before release, and removed any claim that no measurement supports.

Multi-agent operations
